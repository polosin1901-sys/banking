# offersToClients

Сервис персональных рекомендаций банковских продуктов. По идентификатору клиента приложение
проверяет статические правила из первого задания и динамические правила, созданные менеджером,
возвращает объединённый список продуктов без дублей, считает статистику срабатываний и умеет
показывать рекомендации в Telegram.

## Стек

| Слой | Технологии |
|---|---|
| Язык и платформа | Java 17, Spring Boot 4.1.2 |
| Web | Spring MVC (REST), Jackson |
| Доступ к данным | Spring Data JPA (Hibernate), Spring JDBC, HikariCP |
| Базы данных | PostgreSQL 18 — правила и статистика; H2 2.4 — клиентские данные (read-only) |
| Миграции | Liquibase |
| Кэширование | Caffeine |
| Интеграции | Telegram Bot API (`java-telegram-bot-api` 8.3.0) |
| Сборка | Maven Wrapper, Spring Boot Maven Plugin (`build-info`) |
| Тесты | JUnit 5, AssertJ, Spring Boot Test |

## Возможности

1. **Рекомендации** — `GET /recommendation/{user_id}`: три статических правила (Invest500,
   Top Saving, Простой кредит) плюс все подходящие динамические правила, без дублей по `id`.
2. **Управление правилами** — `POST /rule`, `GET /rule`, `DELETE /rule/{id}`: менеджер настраивает
   продукты без изменения кода.
3. **Статистика** — `GET /rule/stats`: счётчик срабатываний по каждому правилу, включая правила
   с `count = 0`; инкремент атомарный.
4. **Telegram-бот** — `/start` показывает справку, `/recommend <username>` присылает рекомендации
   клиенту; срабатывания попадают в статистику.
5. **Сервисные эндпоинты** — `GET /management/info`, `POST /management/clear-caches`.

## Быстрый старт

```powershell
$env:JAVA_HOME='C:\Users\<user>\.jdks\corretto-17.0.19'
.\mvnw.cmd clean package
java -jar target\offersToClients-0.0.1-SNAPSHOT.jar
```

Проверка: <http://localhost:8080/management/info>, Swagger UI — <http://localhost:8080/swagger-ui.html>.

Токен Telegram-бота передаётся только через переменную среды `TELEGRAM_BOT_TOKEN`; без неё
приложение работает, но бот выключен. Подробности — в разделе [Развёртывание](Deployment).
